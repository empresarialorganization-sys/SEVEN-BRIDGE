REGRAS ATUAIS
- Runtime legado 0.8/Opção SOS está aposentado por decisão explícita do usuário e não pode permanecer como fallback ativo, bootstrap, rota de compatibilidade, device padrão ou fonte operacional.
- Não reescrever histórico Git antigo; remover o legado do estado atual, produção, documentação operacional e fontes ativas.
- O caminho canônico é ChatGPT/Codex -> SevenEx -> /mcp -> OAuth no Bridge -> HMAC interno -> Core -> DeviceHub/WebSocket -> Operator 1.1.0.
- SevenEx expõe somente seven_status, seven_command e seven_result.
- device_code identifica execução; não é identidade e nunca entra no schema público das tools nem pode existir como device padrão global.
- Browser ativo é selecionado explicitamente por user_id + workspace_id + session_id; nunca escolher por último visto.
- OAuth bearer do usuário termina no Bridge; nunca repassar bearer ao Core.
- Bridge -> Core usa somente autenticação serviço-a-serviço; nunca registrar ou expor o valor do segredo.
- Não recriar bootstrap, endpoint temporário ou compatibilidade paralela para substituir o legado removido.
- Preservar política de ilhas, foco protegido, acessibilidade, isolamento multiusuário e contrato de versão/protocolo/capacidades.
- Antes de publicar, validar CI e buscar referências residuais ativas ao legado; histórico Git não conta como resíduo ativo.
